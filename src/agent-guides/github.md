# GitHub: как пройти типовые задачи в веб-интерфейсе

<!-- sites: github.com, gist.github.com, github.dev -->

Веб-интерфейс GitHub — React-приложение: половина кнопок открывает выпадающие меню,
а страницы грузятся частями. Порядок ниже экономит шаги.

## 0. Подготовка
1. `browserOpen { url: "https://github.com" }` → `waitForIdle`.
2. Если в правом верхнем углу видна аватарка — вход уже есть (профиль не трогаем).
   Если «Sign in» — проси пользователя войти руками (пароли в чат не запрашиваем;
   сохранённые — через `vaultList` / `vaultFill`).
3. Есть справочник по сайту — читай его до действий (этот файл).

## 1. Создание репозитория
1. Кнопка **«+»** рядом с аватаркой → в меню «New repository».
   ⚠️ Это выпадающий слой: `browserClick { name: "+" }` (или по ref), затем
   `waitForIdle` и клик по пункту «New repository».
2. Или прямой адрес — быстрее: `https://github.com/new`.
3. Поля: «Repository name», «Description» (можно пусто), видимость
   (Public/Private — радио), «Add a README file» — галочка.
4. Кнопка «Create repository» справа внизу (прокрути `browserScroll { how: "bottom" }`).
5. ⚠️ Имя проверяется на ходу: пока занято/неверно — кнопка неактивна, под полем
   красный текст. Не жми вслепую, прочитай подсказку.

## 2. Токен доступа (для git-операций из приложения)
1. Аватарка → «Settings» → в левом меню внизу «Developer settings»
   (это отдельная страница, левое меню после перехода меняется).
2. «Personal access tokens» → «Tokens (classic)» → «Generate new token (classic)».
   Прямой адрес: `https://github.com/settings/tokens/new`.
3. «Note» (имя токена), «Expiration» (срок), «Select scopes» — галочка **repo**
   (для приватных репозиториев и пуша). Для workflow нужен ещё `workflow`.
4. «Generate token» внизу → на новой странице строка `ghp_…` с кнопкой копирования.
   Токен показывается ОДИН РАЗ: скопировать (или прочитать через `browserText`) и сразу
   передать пользователю в Настройки → GitHub. В чат целиком не выводить.
5. ⚠️ Если пользователь не хочет токен — работает OAuth-подключение приложения
   (кнопка «Подключить GitHub»), оно предпочтительнее: меньше ручных шагов.

## 3. Выгрузка (push) локального проекта
- Приложение само умеет это через инструмент `gitPublish` (создаёт репозиторий, первый
  коммит, push). Веб-интерфейс нужен только если репозиторий уже создан:
  адрес берётся из «Code» → HTTPS (`https://github.com/<user>/<repo>.git`).
- ⚠️ Кнопка «Code» — тоже выпадающее меню (копирование URL, GitHub Desktop, ZIP).

## 4. Pull request
1. `https://github.com/<user>/<repo>/compare` — две ветки (base ← compare) выбираются
   в двух списках (Material-подобные, ищи вводом, не скролль).
2. «Create pull request» → заголовок, описание → «Create pull request» ещё раз.
3. ⚠️ Если ветки одинаковые — GitHub скажет «There isn't anything to compare».

## 5. Release / артефакты
`https://github.com/<user>/<repo>/releases/new` → «Choose a tag» (ввод нового тега —
инпут с автодополнением: введи имя, затем выбери «Create new tag»), Title,
описание, «Publish release». Файлы перетаскиваются, но их можно указать и через кнопку
«Attach binaries» (диалог выбора файла — только для реального пользователя).

## 6. Поиск и код
- Глобальный поиск: `/` на странице или `https://github.com/search?q=…&type=code`
  (поиск кода доступен только вошедшим; иначе — предложит войти).
- В репозитории: клавиша `t` включает «файловый» режим (быстрый переход по файлам),
  `s` — поиск. Их можно нажать `browserPress { key: "t" }` после клика по странице.
- ⚠️ Файловый список грузится лениво: длинные папки не видны целиком, пока не
  прокрутишь (`browserScroll { container: "файлы" }`).

## 7. Если что-то «не нажимается»
- Проверь `browserNetwork {}`: 422/403 в ответе — почти всегда точная причина
  (имя занято, нет прав, защита ветки, нужен 2FA).
- Модальные окна ошибок («We couldn't create the repository») содержат причину
  текстом — читай их через `browserText`, а не по памяти.
- Капча и 2FA — только руками пользователя: скажи об этом и жди
  (`browserWait { name: "…" }`), не обходи защиту.
