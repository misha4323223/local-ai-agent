# Гайд по фронту ВК (vk.ru / vk.com) — проверенные методы

> Составлен и проверен в реальной работе: поиск людей, открытие профилей,
> диалоги, отправка сообщений, чтение истории переписок, анализ переписок.
> Все селекторы проверены на практике (аккаунт пользователя).

## 1. Базовые маршруты (URL)

| Действие | URL |
|---|---|
| Поиск людей по имени | `https://vk.com/search?c[section]=people&c[q]=ИМЯ+ФАМИЛИЯ` |
| Профиль по короткому имени | `https://vk.com/<shortname>` (например `jekochka19`) |
| Диалог по ID | `https://vk.ru/im/convo/<user_id>` (пример: `143668553`) |
| Список всех диалогов | `https://vk.ru/im` / `https://vk.com/im` |
| Главная / лента | `https://vk.com/feed` |
| Настройки | `https://vk.com/settings` |

**Важно:** `vk.ru` и `vk.com` взаимозаменяемы. Иногда редиректит на `al_im.php` —
это внутренний AJAX-роутинг ВК, надо просто подождать 2–5 сек и перечитать страницу.

## 2. Ключевые селекторы (проверены на практике)

### Поле ввода сообщения — ГЛАВНОЕ
- ❌ НЕ `textarea` и НЕ `.im_editor` — там `contenteditable`-блок.
- ✅ **`[role="textbox"]`** — единственный стабильно работающий селектор.
- Заполнение: `browserFill(selector="[role=\"textbox\"]", text="...")`
  (при сбое приложение само переключится на способ insertText — клик + очистка + вставка).
- Отправка: `browserPress(key="Enter")` (Shift+Enter — перенос строки без отправки).
- ✅ Проверка отправки: `browserText` — ищем текст в истории диалога
  (сообщение появляется в конце переписки, рядом видно время отправки).

### Навигация
- Кнопка «Написать сообщение» в результатах поиска → сразу открывает диалог (минуя профиль).
- Кнопка «Сообщение» на странице профиля → открывает диалог.
- Список диалогов слева: элементы с текстом имени → `browserClick(text="Имя Фамилия")`.
- Кнопка «Открыть пост» → `text=Открыть пост`.

## 3. Подводные камни (реально встречались)

1. **Ленивая загрузка**: после `browserOpen` контент появляется через 2–5 сек.
   После каждого открытия — `browserWait` или повторный `browserText`.
2. **История диалога грузится долго**: «Загружается...» может висеть 5–10 сек.
   Иногда проще открыть диалог напрямую по URL `vk.ru/im/convo/<peer_id>`.
3. **Сессия слетает при закрытии браузера**: пользователь должен войти сам (QR или пароль).
   Войти за него нельзя — пароли выдумывать запрещено.
4. **Дубликаты имён в поиске**: всегда уточнять адресата (город/возраст/фото/«в друзьях»).
5. **Скриншоты обрезаются**: ВК рендерит очень много DOM-узлов. Для чтения
   состояния надёжнее `browserText`, скриншот — только для визуальной верификации.
6. **`browserText` отдаёт историю вместе с левым меню**: фильтровать по датам/именам,
   искать текст сообщений по имени собеседника и времени.
7. **Новые вкладки открываются БЕЗ сессии** — работать в существующей вкладке,
   не плодить новые. Закрывать только конкретные tabId, не «all».
8. **Поле ввода**: не использовать `textarea`-селекторы — в ВК их нет для сообщений.

## 4. Проверенный сценарий: отправить сообщение человеку

```
1. browserOpen("https://vk.com/im") — если браузер не открыт
   → если форма входа: пользователь входит сам (QR/пароль), агент ждёт
2. browserOpen("https://vk.com/search?c[section]=people&c[q]=Имя Фамилия")
3. browserText → смотрим результаты (имя, город); уточнить у пользователя, если дубликаты
4. browserClick("text=Написать сообщение") → открывается /im/convo/<id>
   (или browserClick("text=Имя Фамилия") → профиль → browserClick("text=Сообщение"))
5. browserWait 2–5 с → browserText → подтвердить, что диалог открыт
6. browserClick(selector: "[role=\"textbox\"]")
7. browserFill(selector: "[role=\"textbox\"]", text: "текст сообщения")
8. browserPress(key: "Enter")
9. browserText → проверить, что текст сообщения появился в истории ✅
   (не видно → повторить шаги 6–8)
```

## 5. Проверенный сценарий: анализ переписок

1. Открыть `vk.ru/im` (список диалогов), подождать 3–5 сек.
2. `browserText` — список диалогов виден как имена в левом меню.
3. Открыть диалог: клик по имени в списке ИЛИ напрямую `vk.ru/im/convo/<peer_id>`.
4. Прочитать `browserText` (~15 000 симв.) — обычно хватает на суть.
5. Если «Загружается...» — подождать 5 сек, перечитать; если не грузится —
   открыть URL напрямую с peer_id из параметров ссылки.
6. Длинную историю читать частями: листать вверх (`browserPress key: "PageUp"`),
   перечитывать `browserText`, собирать текст (2–4 прохода).
7. Проанализировать по методологии agent-guide:chat-analysis: тип отношений,
   темы, суть; составить таблицу.
